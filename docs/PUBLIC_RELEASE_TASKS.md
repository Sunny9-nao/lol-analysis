# 一般公開（Public Release）に向けたタスクリスト

本プロジェクトをローカルMVPから一般利用可能なサービスへ移行するための実行計画である。2026-09-05の評価では、**一般公開判定はNo-Go** とした。詳細な根拠と検証結果は[品質評価レポート](./QUALITY_ASSESSMENT_2026-09-05.md)を参照する。

## 優先順位と公開ゲート

- **P0**: 未完了のまま外部公開、公開alpha、公開betaを行わない項目。
- **P1**: P0完了後、限定betaから一般公開へ進む前にステージングで実証する項目。
- **P2**: 公開品質・成長・公開リポジトリ運用を高める項目。収益化・共有機能を出す前に該当項目を完了する。

一般公開の承認条件は、P0/P1の完了、CI必須ゲートの成功、ステージングでの復元・障害・認可テストの成功、運用担当者によるリリース承認とする。

## P0: 外部公開を阻害する項目

### 1. 認証・認可とメモのデータ所有権

- [x] **認証方式を一つに決定する**: 独自アカウント認証（JWT）＋Riot ID連携を採用。ログイン・サインアップ・ログアウトおよびセッション保持を実装。
- [x] **所有権モデルを実装する**: `(User × MatchParticipant) -> MatchNote` の複合一意制約モデルを構築。同一サモナーを複数ユーザーが登録してもメモが完全に独立・秘匿される設計を確立。
- [x] **閲覧可視性を設計する**: 戦績データはOP.GG同様にオープン閲覧可能とし、反省メモは本人（current_user）のみが作成・更新・閲覧可能に設計・実装。
- [x] **認可テストを追加する**: 未認証アクセス、別ユーザーからのメモ更新・取得遮断、同一サモナー連携時のメモ分離をRSpecリクエストスペックで検証済み。
- [ ] **認証情報を安全に扱う**: Cookie利用時は`Secure`、`HttpOnly`、`SameSite`、CSRF対策を設定し、トークンをログ・URL・クライアント状態へ出さない。

### 2. Riot APIの公開利用準拠と耐障害性

- [ ] **Riot製品を登録・監査に通す**: Developer Portalで製品登録し、一般公開前にProduction API Keyを取得する。製品機能の変更時は再監査要否も確認する。Personal API Keyで公開alpha/betaを行わない。（※ユーザー承認待ち）
- [ ] **ゲーム整合性を確認する**: チャンプセレクト時のカンペ・対面分析がRiotのゲーム整合性ポリシーと製品審査に適合することを確認し、必要ならDeveloper Relationsへ問い合わせる。
- [x] **429を`Retry-After`準拠で制御する**: RiotApiClient にてクラスレベルの共有レートリミット状態管理、`Retry-After`ヘッダ準拠の待機、ジッター、最大3回リトライを実装・検証済み。
- [x] **外部API呼び出しに上限を設ける**: open 3s / read 5s タイムアウト、5xxエラー時の一時障害指数バックオフ、Faradayタイムアウト制御を実装・検証済み。
- [ ] **同期を非同期化する**: 検索リクエストで大量の試合・タイムラインを直列取得しない。ジョブキュー、冪等性キー、重複排除、進捗ポーリングまたは通知を設計する。
- [ ] **Riot APIキーをローテーションする**: 実キーを失効・再発行し、Secret Managerまたはホスティングのsecret注入で供給する。キーのローテーション、漏えい時の停止、再発行の手順を文書化する。

### 3. 公開APIと本番通信の防御

- [x] **本番CORSを環境別に設定する**: 環境変数 `ALLOWED_ORIGINS`（未設定時はlocalhost安全許可）、許可メソッドをGET/POST/OPTIONS/HEADに限定して実装・検証済み。
- [ ] **HTTPSを強制する**: TLS終端を構成し、`force_ssl`、HSTS、secure cookie、本番URLを設定する。Host許可リストとヘルスチェック例外も設定する。
- [ ] **自APIのレート制限を導入する**: IP・認証済みユーザー・検索対象を考慮した制限を設定し、429応答、監視、除外ルールをテストする。
- [x] **GraphQLの濫用対策を実装する**: `max_depth 12`、`max_complexity 300`、`max_query_string_tokens 5000`、本番環境でのIntrospection無効化を実装・検証済み。
- [x] **セキュリティヘッダを設定する**: Railsデフォルトヘッダに加え、Next.js側で `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` を設定済み。
- [ ] **秘密情報スキャンを必須化する**: Git hookまたはCIで秘密情報を検出し、履歴・ログ・ビルド成果物への混入時の対応手順を作る。

### 4. 法務・プライバシー・データ保持の最低条件

- [ ] **利用規約を公開する**: 提供範囲、禁止事項、免責、問い合わせ先、サービス変更・終了条件を明記する。
- [ ] **プライバシーポリシーを公開する**: Riot ID、戦績、生JSON、メモ、IP/ログ、分析データの取得目的、保存先、保持期間、第三者提供、問い合わせ方法を明記する。
- [x] **Riotの指定免責文を視認可能な場所に掲示する**: フッター等にLegal Jibber Jabberの現行指定文言を掲載済み。
- [ ] **データ主体の操作を実装する**: 本人によるアカウント削除、メモ・保存戦績の削除、エクスポート、同意撤回の受付・処理手順を決める。
- [ ] **データ分類と保持期間を確定する**: ゲスト検索データ、登録利用者データ、生JSON、監査ログ、バックアップごとに保持目的・期限・削除責任者を定義する。詳細は[データ保持・検索設計](./DATA_RETENTION_AND_SEARCH.md)と整合させる。

## P1: 一般公開前にステージングで実証する項目

### 5. データベース、ストレージ、復旧

- [ ] **PostgreSQLへ移行する**: SQLite依存を外し、接続、マイグレーション、インデックス、バックグラウンドジョブ用DBを本番構成で検証する。
- [ ] **バックアップと復元を運用化する**: 暗号化した自動バックアップ、保存世代、アクセス制御、復元手順、定期復元テストを整備し、RPO/RTOを決める。
- [ ] **データ削除・Cold Storageバッチを実装する**: ゲストの期限切れデータをパージし、古い生JSONは削除またはCold Storageへ退避する。削除前後の整合性と失敗時の再実行をテストする。
- [ ] **ログの個人情報を最小化する**: Riot ID、メモ本文、認証情報、外部API本文を無制限に残さない。マスキング・保持期限・アクセス権を設定する。

### 6. 性能、検索、同期のスケール設計

- [ ] **GraphQLをページングする**: 試合履歴・対面詳細にカーソルページングと最大件数を導入し、全件`to_a`による無制限なメモリ利用をなくす。
- [ ] **集計と外部レスポンスをキャッシュする**: キャッシュ対象、TTL、失効契機、スタンピード防止、障害時の扱いを定義する。Data Dragonの更新とキャッシュ無効化も一元化する。
- [ ] **N+1とクエリ予算を継続監視する**: Dataloader/includesを実データ量で検証し、主要クエリのSQL件数・応答時間に予算を設ける。
- [ ] **負荷試験を実施する**: 同時検索、再同期、429、Riot 5xx、DBロック、ジョブ再実行をステージングで試し、許容レイテンシと破綻時の挙動を記録する。

### 7. 本番インフラ、デプロイ、運用

- [ ] **ステージングと本番を構築する**: フロントエンド、Rails API、PostgreSQL、ジョブワーカー、ドメイン、DNS、TLS、環境変数を分離する。
- [ ] **本番Dockerイメージを検証する**: 非root実行、最小権限、イメージ脆弱性スキャン、ヘルスチェック、ログ出力、DBマイグレーションを含めて確認する。
- [ ] **デプロイとロールバックを自動化する**: 段階的なステージング反映、マイグレーション失敗時の停止、前バージョンへの復帰、手順書を整備する。
- [ ] **可観測性を導入する**: 例外追跡、可用性監視、構造化ログ、Riot APIの429/5xx率、同期失敗率、ジョブ遅延、GraphQLレイテンシのメトリクスとアラートを設定する。
- [ ] **障害対応を準備する**: 当番・連絡先、インシデント記録、Riot障害時の告知、バックアップ復元、秘密情報失効、ロールバックのRunbookを作成する。

### 8. CI/CDと公開品質ゲート

- [x] **GitHub Actionsをリポジトリ直下に配置する**: `.github/workflows/ci.yml` を新設し、PRおよびpushトリガーで実行される構成を配備済み。
- [x] **バックエンド検証を必須化する**: CIにRSpecテストおよびRuboCopリントを組み込み済み。
- [x] **フロントエンド検証を必須化する**: CIにESLint、TypeScript/Next.js build、Playwright E2Eを組み込み済み。
- [x] **品質基準を合意する**: RuboCop 0 offenses、ESLint 0 warningsを達成し、構文警告・スタイル違反を排除。
- [ ] **公開前テストケースを追加する**: 認可拒否、429/5xx、タイムアウト、同期ジョブ重複、削除・エクスポート、復元、モバイル表示、アクセシビリティを自動・手動の両方で検証する。

### 9. 利用品質とアクセシビリティ

- [ ] **モバイル表示を修正・検証する**: 320px、375px、414px、768pxで横あふれ、文字切れ、操作不能な制御がないことを自動テストと実機で確認する。
- [ ] **モーダルとキーボード操作を整備する**: フォーカストラップ、初期フォーカス、閉じた後のフォーカス復帰、ESC、アクセシブルな名前、適切なラベルを実装する。
- [ ] **エラー・空状態・再試行を整備する**: Riot障害、認可拒否、通信断、同期中、データ不足を区別し、利用者が次に取る操作を示す。
- [ ] **詳細キャッシュをスコープする**: サモナー、使用チャンピオン、ロール、対戦相手を含むキーまたは適切な無効化で、切替後の古い詳細データを表示しない。

## P2: 公開品質と継続運用を高める項目

### 10. SEO、共有、計測

- [ ] **OGPとXカードを設定する**: サービス名、説明、共有画像、canonical URL、robots/sitemapを実装する。
- [ ] **動的共有を可視性設計と一緒に実装する**: サモナー分析やメモをURL共有する場合は、本人の明示操作、公開期限、非公開既定、削除後の無効化を設計してから実装する。
- [ ] **アクセス解析を適法に導入する**: GA4、Vercel Web Analytics等を選定し、地域に応じた同意、オプトアウト、データ最小化、プライバシーポリシー反映を行う。

### 11. フロントエンドとコンテンツの改善

- [ ] **画像配信を最適化する**: `next/image`または適切なloaderを使い、Data Dragon画像のキャッシュ、サイズ、失敗時表示を整備する。
- [ ] **Data Dragonバージョン管理を一元化する**: 複数コンポーネントに散在する固定バージョンをなくし、更新検知、キャッシュ更新、表示互換性をテストする。
- [ ] **LP・ティア推移の提供可否を決める**: ADRで定義したLeague-V4由来の機能を提供する場合は、データモデル、同期頻度、表示の正確性、Riotポリシーを確認する。

### 12. 公開リポジトリと収益化の準備

- [ ] **公開リポジトリの運用文書を追加する**: LICENSE、SECURITY.md、脆弱性報告窓口、CONTRIBUTING.md、第三者ライセンス一覧を整備する。
- [ ] **収益化前のRiot準拠を確認する**: 収益化する場合は、製品承認状態、無料利用枠、変形的価値、広告配置、料金表示をRiotポリシーと照合する。
