# [ADR-0007] 対面分析（Matchup Analysis）機能の設計とGraphQLスキーマ策定

- **ステータス**: Accepted
- **決定日**: 2026-09-05
- **決定者**: チーム / 開発者

## コンテキスト（背景・課題）
当プロジェクト（`lol-analysis`）は、League of Legends の戦績分析・振り返り支援アプリケーションを目指している。
一般的な戦績検索サービス（OP.GG等）との明確な差別化と、プレイヤーに対するコアバリュー提供のためには、「特定チャンピオンを使用した際の、対面チャンピオン（Matchup）ごとの勝率・指標・過去の反省メモ・ビルド」を瞬時に振り返ることができる機能が不可欠である。
本機能を設計・実装するにあたり、分析の主軸、取得指標、導線、およびGraphQLスキーマの配置についてアーキテクチャ上の意思決定を行う。

## 検討した選択肢
1. **全体メタ統計（Global Stats）を主軸とするアプローチ**
   - 登録されている全ユーザーの全試合データを合算し、メタ的な有利不利（カウンター相性）を算出する。
   - デメリット: 初期段階ではデータ母数が不足し偏りが出る。また「個人の振り返り支援」というプロダクト本来の目的に直結しにくい。
2. **特定サモナー視点の個人戦績・振り返りを主軸とするアプローチ（採用）**
   - プレイヤー個人の特定チャンピオン使用時の対面戦績・メモ・CS/分・ビルドを振り返る。
   - 導線として「自チャンプ選択」→「対面サマリ一覧」→「特定対面の試合詳細・メモへドリルダウン」を統合する。
   - メリット: プレイヤーの直接の反省・上達に繋がり、メモ機能（`MatchNote`）の価値を最大化できる。

## 決定事項 (Decision)
1. **個人特化のドリルダウン型対面分析の採用**:
   - サモナー詳細（`SummonerType`）配下に対面分析用のリゾルバを追加する。
   - `playedChampions`: 使用チャンピオン一覧と試合数・勝率
   - `matchupSummaries`: 対面チャンピオン別の集計サマリ（試合数、勝率、平均KDA、平均CS/分、Hard/Even/Easyタグ比率、最新メモ）
   - `matchupDetail`: 特定対面との全試合記録（アイテム、スペル、スコア、反省メモ）
2. **CLASSICモード限定とレーンフィルタ**:
   - 対面分析の精度を担保するため、通常戦・ランク戦（CLASSIC）のみを対象とし、特殊モード（ARAM等）や対面が記録されていない試合は除外する。
   - ロール（`position`: TOP, JUNGLE, MIDDLE, BOTTOM, UTILITY）による任意絞り込みに対応する。
3. **同期試合数の拡張**:
   - 初回同期で十分な対面データ母数を確保するため、Riot APIからの直近試合取得数を 3件 から 15件 に拡張する。
4. **N+1クエリ対策の徹底**:
   - 集計サービスクラス `MatchupAnalysisService` において、`includes` によるリレーションの一括ロードと、チャンピオンマスタ（`Champion`）のインデックスマップを用いた一括紐付けを行い、対面数・試合数が増加してもSQLクエリ数が一定となるよう設計する。

## 結果と影響 (Consequences)
### ポジティブな影響（メリット）
- プレイヤーは「対ダリウスで過去にどんなメモを残したか」「勝率はどれくらいか」「何を意識すべきか」を即座に確認できるようになり、アプリのコア価値が実現された。
- GraphQLスキーマが明確に整理され、フロントエンド（Next.js）でのUI構築が容易になった。
- N+1クエリ検証テストにより、データ量が増加しても安定したレスポンス速度を維持できる。

### ネガティブな影響 / トレードオフ
- 初回同期時の試合数を15件に増やしたため、1サモナーあたりの初回APIリクエスト数が約17リクエストに増加した（Riot API個人キーの制限: 2分あたり100リクエスト）。短時間に多数の新規サモナーを検索するとレートリミットに達しやすくなる。
