# [ADR-0009] 分析スコープのランクマッチ（Ranked Solo/Duo & Flex）への限定とqueue_id管理

- **ステータス**: Accepted
- **決定日**: 2026-09-05
- **決定者**: チーム / 開発者

## コンテキスト（背景・課題）
当プロダクトは「プレイヤー自身がランクマッチ（Ranked）を勝ち上がり、ランクを上げるための振り返り・分析」を第一目的としている。
従来の設計ではサモナーズリフト全般（`game_mode: "CLASSIC"`）を対象としていたため、ノーマル戦（Normal Draft / Blind / Quickplay）などのお試しピックやエンジョイ試合が混ざり、対面勝率や反省メモの信頼性にノイズが生じる恐れがあった。

## 検討した選択肢
1. **全モード（CLASSIC）を維持し、UI上のフィルタで切り替える**:
   - データとしては残るが、初期表示でノイズが混ざり、「ランクを上げるためのツール」としての焦点がぼやける。
2. **スコープをソロ/デュオ ランクマッチ（queueId: 420）に特化する（採用）**:
   - `matches` テーブルに `queue_id` カラムを新設し、対面分析の基底スコープ（`base_scope`）を競技性の中心であるソロ/デュオ ランク（`SOLO_DUO_QUEUE_ID = 420`）に限定する。フレックスランク（440）やノーマル戦は対象外とする。
   - メリット: ソロランクを上げるための真剣勝負のデータのみが集計され、カウンター相性や反省メモの精度が極大化される。

## 決定事項 (Decision)
1. **`matches` テーブルへの `queue_id` の追加**:
   - マイグレーションを作成し、`queue_id: integer`（インデックス付き）を追加。
   - 既存の全試合レコードに対して `raw_info["info"]["queueId"]` から値をバックフィルした。
2. **`MatchupAnalysisService` の絞り込み**:
   - `SOLO_DUO_QUEUE_ID = 420` を定義し、`base_scope` で `where(queue_id: SOLO_DUO_QUEUE_ID)` に限定。
3. **GraphQL API と UI へのキュー種別露出**:
   - `MatchParticipantType` に `queue_id` および `queue_name`（"Ranked Solo", "Ranked Flex" 等）を追加。
   - 試合カード上でキュー種別を明示的にバッジ表示する。

## 結果と影響 (Consequences)
### ポジティブな影響（メリット）
- ノーマル戦のノイズが完全に排除され、ユーザーの主力ピック（Renekton 18試合 / Jax 14試合）におけるリアルな相性と反省が純粋に可視化された。
- SQLレベルでインデックス検索されるため、集計パフォーマンスも向上した。
