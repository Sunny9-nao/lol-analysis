# [ADR-0003] 生データ(Raw JSON)保持と正規化テーブルのハイブリッド設計

- **ステータス**: Accepted
- **決定日**: 2026-09-05
- **決定者**: 開発者

## コンテキスト（背景・課題）
Riot Games API の試合詳細（Match-V5）は、1プレイヤーあたり150以上のスタッツ項目、1試合あたり10人分の詳細データを含む。
- すべてを個別のカラムとして定義すると、マイグレーションやスキーマの保守コストが跳ね上がる。
- 一方で、必要な項目のみを抽出して保存し残りを破棄すると、将来新たな指標（ピン回数、被ダメージ、ルーン等）を分析したくなった際に、Riot API を再リクエストしなければならず、APIレート制限（100回/2分）や24時間有効期限に阻まれる。

## 検討した選択肢
1. **選択肢A (全項目をカラム化)**: 100以上のカラムを持つ巨大テーブルを作る。保守性が著しく低下する。
2. **選択肢B (最小限の項目のみカラム化し、他は破棄)**: 将来の拡張性が失われ、API再リクエストが必要になる。
3. **選択肢C (生JSON保存 + 正規化テーブルのハイブリッド)** 【採用】:
   - 試合全体の生JSON (`matches.raw_info`) およびプレイヤー個別の生JSON (`match_participants.raw_participant`) をそのまま保存。
   - よく利用する検索・集計キー（自チャンプ、対面チャンプ、勝敗、KDA、CS等）は正規化カラムとしてインデックスを付与。

## 決定事項 (Decision)
以下のテーブル構成を採用する：
- `summoners`: サモナーメタデータ + `raw_data` (JSON)
- `matches`: 試合メタデータ + `raw_info` (10人分を含む生JSON)
- `match_participants`: 自プレイヤーの正規化戦績 + `opponent_champion_name`（対面特定）+ `raw_participant` (本人分156項目生JSON)
- `match_notes`: プレイヤーの試合ごとの振り返りメモ・タグ
- `champions`: チャンピオンマスタ（名前、称号、画像URL等）

## 結果と影響 (Consequences)
### ポジティブな影響（メリット）
- **拡張性**: 将来の機能追加時も、外部APIを叩き直すことなくローカルDB内のJSONから新しい集計・カラムを再生成できる。
- **検索性能**: GraphQL クエリでは正規化されたカラムを利用するため、高速な絞り込みやソートが可能。
- **対面分析**: `opponent_champion_name` を正規化して持つことで、「対ヨリック戦の勝率・メモ」などの対面特化分析が容易になる。

### ネガティブな影響 / トレードオフ
- JSONを保存するためDBサイズが大きくなる（ただしローカルSQLiteでは数十MB程度で全く問題にならない）。
